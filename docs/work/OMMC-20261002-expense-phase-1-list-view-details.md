- **Portal list defect:** The actual Filament Expense table source contained `expenseType.name` as its display column relationship and filter relationship, while the database’s ExpenseType display field is `label`. These list-request references could request the nonexistent `expense_types.name` column. The table now references `expenseType.label`, and its alphabetical default uses a correlated `expense_types.label` subquery. The ordering regression test checks the generated sort SQL uses label and excludes `expense_types.name`. Retest in the target Portal runtime remains part of acceptance.
- **Global blank-page diagnosis and correction:** The current HTTP response contained the `ExpensePage` main content and included reader, so Blade page binding and partial inclusion were working. In Chrome DevTools, the actual page emitted `Uncaught SyntaxError: Invalid or unexpected token` at `expense-page:706`; then `ommcExpenseReader is not defined`, followed by Alpine `init`, `isWide`, `expenseItems`, and `selectedExpense` reference errors. Literal backslashes before JavaScript template-literal delimiters in the Blade script caused the syntax failure and left the x-show panes hidden. Those escapes are removed. Earlier 13:20 Laravel logs reported a missing partial, but the current 13:29 response already included it; those earlier entries did not match the observed current browser failure. The earlier Livewire-only test asserted markup strings without evaluating the inline JavaScript, so it missed the parse error. New authenticated HTTP route tests cover populated, empty, and failed global page renders, including an assertion for the malformed escape sequence.
- **Global Expense orientation diagnosis and correction:** The pre-existing generated Filament theme CSS in `public/build` did not contain either `.lg\:grid{display:grid}` or the reader’s `lg:grid-cols-[minmax(17rem,0.38fr)_minmax(0,0.62fr)]` rule, although the rendered Blade included both classes. At Tailwind’s `lg` breakpoint (64rem), the missing display and column rules left the two panes stacked. `npm run build` regenerated the ignored runtime assets; the theme CSS now contains both rules inside `@media (width>=64rem)`. The 38/62 proportional columns, global `isWide` list/detail visibility, and each pane’s bounded independent overflow remain aligned at the same 1024px threshold.
