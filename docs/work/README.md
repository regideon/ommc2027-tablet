# Durable Work notes

Create one Markdown note per implementation Work at:

`docs/work/<work-id>.md`

For cross-repository Work, use the same Work ID and maintain materially
equivalent notes in both repositories. Update notes only when continuation
state materially changes; do not create per-turn logs.

Each note must include:

- Work ID and title;
- objective and affected repositories;
- Human-authorized scope and accepted decisions;
- implementation constraints;
- current Work state;
- implementation and terminal authorization status;
- task-owned files/components;
- unrelated/pre-existing worktree changes to preserve;
- significant implementation decisions;
- validation and manual-acceptance results;
- blockers and remaining work;
- delivery evidence status.

Do not record secrets, passwords, tokens, credentials, environment contents,
machine-specific configuration, or transcript dumps.
