# OMMC-20261007-tablet-customer-search-and-push

- **Title:** Add local Customer search and Customer-only push actions on Tablet
- **Objective:** Improve Customer directory usability and push Customers after creation or from the Customer module without invoking global synchronization.
- **Repositories:** Tablet `ommc2027-tablet` only.
- **State:** TERMINAL_DELIVERED

- **Constraints:** Do not inspect or modify Portal. Preserve paginated/checkpointed Customer pull, current Customer role/Access visibility, global sync behavior, and unrelated worktree state. No migrations, deployment, commit, or push.

- **Accepted decisions:** Search is local, debounced, case-insensitive partial matching over existing Customer and supported local location data. Manual Customer push processes pending and retryable failed Customers only. Creation remains locally authoritative and network failure cannot undo it. No automatic push after edits.
- **QA relationship:** Addresses Tablet QA issue `Created customer unable to search`; Tablet search includes Customer Code / `unique_id`. The separate Portal issue `Unable to search via customer code` is not resolved here. Other reported QA issues remain separate follow-up work.
- **Implementation:** CustomerPage now applies debounced local search after the existing active, role, Access, and pulled-scope filters. Search covers name, `unique_id`, address, municipality, province, barangay, Area Cluster, and Specific Region. A Customer-only eligibility query and push primitive now serve global push, exact-Customer push, and pending/retryable-Customer push. Customer creation pushes only after its local transaction commits; failure leaves the local Customer intact and reports that synchronization remains pending. The Customer header exposes Search, Pull, Push, and Add actions using Material Symbols. Existing pull component, pagination, checkpointing, progress, and resume logic remain in place.
